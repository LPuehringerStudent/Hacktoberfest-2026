# Challenge checklist

We enter all four. A project may enter multiple categories as long as it meets **every** requirement of each. Tick these off as we go. Before submitting, every box should be ✅.

## 1. Best Open-Source AI Project (DigitalOcean): core challenge

Requirement: an original project using open-source or open-weight AI **as an essential component**.

- [ ] Gemma 4 (open-weight) is on the critical path. Without it, the app doesn't work.
- [ ] Repo is **public** on GitHub.
- [ ] Open-source license is **obvious**: `LICENSE` file at root + "License" section in README. (The submission form has no license field; judges check the repo.)
- [ ] The Lovable frontend repo is also public and has a `LICENSE` file.
- [ ] README explains which open models are used and how.
- [ ] Nice to have: a fallback path or note on how to run Gemma 4 locally (Ollama / HF weights), to show it's truly open.

## 2. Best Use of Gemma 4

Gemma 4 via the Gemini API. Judges will want to see it used *well*, not just called once.

- [ ] Uses at least one Gemma 4 strength beyond plain chat: **image input (multimodal)**, **function calling**, **structured JSON output**, system instructions.
- [ ] Model ID visible in code/README (`gemma-4-26b-a4b-it` or `gemma-4-31b-it`).
- [ ] Demo shows the Gemma 4 feature clearly on screen.

## 3. Best Use of ElevenLabs (event prize)

- [ ] **Check eligibility:** only participants who registered by 1 pm, 27 Oct. Confirm at least one teammate qualifies, and that person submits.
- [ ] ElevenLabs is meaningful in the UX (voice output, speech input, voice agent, sound effects…), not decorative.
- [ ] Demo has audible voice. Make sure the recording captures audio.

## 4. Best Use of Lovable (event prize)

- [ ] Frontend is built in Lovable. Keep the Lovable project and its git history as evidence.
- [ ] Claim the 1-month Pro perk if eligible.
- [ ] README links to the Lovable repo and/or published Lovable URL.
- [ ] Demo shows the Lovable-built UI.

## MLH judging criteria (equal weight)

| Criterion | What we do about it |
|---|---|
| **Technology** | Multimodal + function calling + voice in one flow. Explain the hard part in the demo. |
| **Design** | Lovable gives us a polished UI. Spend real time on the UX flow. |
| **Completion** | Feature freeze at deadline − 2h. A working small thing beats a broken big thing. |
| **Learning** | README "What we learned" section. Mention what was new for each of us. |
